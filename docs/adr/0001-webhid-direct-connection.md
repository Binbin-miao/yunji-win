# ADR-0001：网页版用 WebHID 在浏览器内直连设备

- 状态：已接受（2026-10-31）
- 相关：`web/`、`docs/web/`

## 背景

需要让用户在完全不安装软件的前提下调音。设备是 USB HID，协议基于 `0x4B` 报告帧。

浏览器想要碰 HID 设备，只有两条路：让用户装一个本地小服务，网页通过 WebSocket 把命令转给它；或者用浏览器自带的 WebHID。

## 决定

采用 **WebHID 直连**：协议层整体用 JS 重写（帧构造、8 段打包、双二阶响应计算），不引入任何本地服务。

## 后果

**得到**

- 部署是纯静态的，丢在 GitHub Pages 上就行，没有安装步骤、没有防火墙弹窗、没有后台进程
- 不需要为 Windows/macOS/Linux 各维护一份本地服务
- 与桌面版共用同一套协议，两边行为可以互相校对

**付出**

- 只有 Chromium 内核能用（Chrome / Edge 113+）。Firefox 与 Safari 用户完全无法使用，这是硬边界，不是可以补的洞
- 首次连接必须由用户点击并授权，不能自动重连到上一次的设备
- 浏览器进程的生命周期即会话生命周期，没有常驻后台、没有开机自启
- 无法访问文件系统的任意路径，预设只能存 `localStorage` 或让用户下载

**被否决的方案**

- 本地 Python 服务 + WebSocket 桥：能力更全（能读日志、能访问任意路径），但要用户装东西，且失去「网页版」的全部意义
- Electron 套壳：那是把桌面版换个皮，不是网页版

## 复核触发条件

若将来 Firefox 或 Safari 支持 WebHID，或设备改用标准 USB Audio Class 驱动（不再需要私有 HID 控制），本决定应重新评估。
