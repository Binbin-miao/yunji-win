# 硬件通信与 DSP 协议规范

本文档为 `yunji-win` 移植项目所归纳整理的开源硬件通信协议规范，供社区开发者、音频极客进行多平台适配（如 Linux / macOS）或二次开发参考。

---

## 一、双品牌协议架构概览

本工具支持的 Type-C 音频解码小尾巴按硬件厂商与通信协议划分为两大类：

| 硬件阵营 | 典型代表 / 芯片 | USB 接口类型 | 通信底层 | 传输特征 |
| :--- | :--- | :--- | :--- | :--- |
| **旋润 (XuanRun)** | VID: `12230` (`0x2FC6`)<br>CS43198 系列 | Vendor Specific / Bulk / Control | USB 控制传输 (`controlTransfer`) | 双向控制传输，前缀 `0xC1 0xA6` |
| **TTGK** | VID: `13058` (`0x3302`)<br>CB1200 / CB5100 系列 | HID (Human Interface Device) | USB 中断端点 (`Interrupt Transfer`) | Windows 原生免驱直通，前缀 `0x4B` |

## 二、TTGK HID 协议规范

### 1. 物理层与端点规范
- **HID 报告特征**：输入/输出报告长度均为 **64 字节**。
- **报告 ID**：TTGK 协议前缀魔数 `0x4B` 在 Windows HID 驱动中直接兼作 Report ID，通信时通过免驱 `hidapi` 直接对端点发送 64 字节报文即可直通。

### 2. 帧格式
- **发送格式 (Host -> Device)**：
  `[0x4B, 0x01, CMD, LEN, PAYLOAD..., (补零至 64 字节)]`
- **接收格式 (Device -> Host)**：
  `[0x4B, 0x80, CMD, PAYLOAD..., (总长 64 字节)]`

### 3. 核心命令表

| CMD | 功能 | 说明 |
| :--- | :--- | :--- |
| `0x02` | 麦克风增益 | 读写 ADC 麦克风音量档位 (0 ~ 24) |
| `0x03` | 硬件 DAC 音量 | 读写 DAC 硬件输出音量 (0 ~ 60) |
| `0x04` | 提交并保存 | 执行配置持久化写入芯片 Flash / EEPROM |
| `0x09` | EQ 单波段读写 | 读写指定波段的二阶滤波器系数与频点参数 |
| `0x0A` | EQ 全局生效提交 | 提交命令：`4B 01 0A 04 00 00 FF FF`，使写入的 EQ 参数立即在 DSP 中生效 |
| `0x0C` | 查询固件版本 | 返回当前固件版本字符串（如 `0.8`） |
| `0x11` | 硬件滤波模式 | 切换 DAC 内置的插值滤波模式 (0 ~ 4) |
| `0x16` | 声道平衡 | 调节左右声道差分平衡 (-18 ~ +18) |
| `0x18` | LED 灯控 | 开关指示灯 (0=开, 1=关) |
| `0x19` | 增益高低切换 | 切换耳放高/低增益输出档位 (0=低增益, 1=高增益) |

## 三、8 段双二阶 (Biquad) EQ 算法与封包规范

TTGK 系列设备搭载硬件音频 DSP，支持 8 段全参数峰值均衡（Peaking Filter）。

### 1. 系数生成公式 (Peaking EQ)
- **基准 DSP 采样率**：固定为 $F_s = 96000\text{ Hz}$。
- **计算中间量**：
  $$A = 10^{\frac{\text{gain}}{40}}$$
  $$\omega_0 = \frac{2\pi \cdot f_c}{F_s}$$
  $$\alpha = \frac{\sin(\omega_0)}{2Q}$$
- **二阶转移函数未归一化系数**：
  $$b_0 = 1 + \alpha \cdot A$$
  $$b_1 = -2\cos(\omega_0)$$
  $$b_2 = 1 - \alpha \cdot A$$
  $$a_0 = 1 + \frac{\alpha}{A}$$
  $$a_1 = -2\cos(\omega_0)$$
  $$a_2 = 1 - \frac{\alpha}{A}$$
- **归一化处理**：
  全部除以 $a_0$ 得到标准差分方程系数：
  $b_0' = \frac{b_0}{a_0},\; b_1' = \frac{b_1}{a_0},\; b_2' = \frac{b_2}{a_0},\; a_1' = \frac{a_1}{a_0},\; a_2' = \frac{a_2}{a_0}$

### 2. 定点数定标 (Q30 量化)
DSP 采用 32 位有符号定点数格式，标度为 $2^{30}$ (Q30)：
$$\text{Fixed}(x) = \text{round}(x \times 2^{30})$$
打包为 5 个 32 位小端整数：`[b0, b1, b2, -a1, -a2]`（共 20 字节）。

### 3. 单波段 37 字节报文结构
发送 `CMD 0x09` 时，Payload 结构如下：

| 字节偏移 | 长度 | 字段含义 | 说明 |
| :--- | :--- | :--- | :--- |
| `0..7` | 8 字节 | 包头 | `0x4B, 0x01, 0x09, 0x18, 0x00, band_index, 0x00, 0x00` |
| `8..27` | 20 字节 | DSP 滤波系数 | 5 个 32-bit 小端整数 `[b0, b1, b2, -a1, -a2]` |
| `28..29`| 2 字节 | 中心频率 $f_c$ | 16-bit 小端无符号整数 (Hz) |
| `30..31`| 2 字节 | Q 值标志 | 固定常量 `0xC0, 0x00` |
| `32..33`| 2 字节 | 增益量 | `[floor(gain * 256) & 0xFF, floor(gain) & 0xFF]` |
| `34` | 1 字节 | 类型标记 | `0x02` (Peaking) |
| `35` | 1 字节 | Offset | 波段索引偏移量 |
| `36` | 1 字节 | 尾符 | `0x00` |

## 四、旋润 (XuanRun) 控制传输协议规范

### 1. USB 请求参数
- **写入请求 (Host -> Device)**：
  - `bmRequestType = 0x43` (Vendor, Endpoint, Host to Device)
  - `bRequest = 0xA0`
  - `wValue = 0`
  - `wIndex = 0x09A0`
  - `data = 7 字节 payload`
- **读取请求 (Device -> Host)**：
  - 先写入触发查询帧，然后调用：
  - `bmRequestType = 0xC3` (Vendor, Endpoint, Device to Host)
  - `bRequest = 0xA1`
  - `wValue = 0`
  - `wIndex = 0x09A0`
  - `length = 7`

### 2. 帧格式
固定 7 字节报文：
`[0xC1, 0xA6, CMD, ARG0, ARG1, ARG2, ARG3]`

### 3. 核心命令表

| CMD | 功能 | 说明 |
| :--- | :--- | :--- |
| `0x01` | 数字滤波模式 | ARG0 为滤波档位 (0 ~ 4) |
| `0x02` | 增益模式 | ARG0 切换增益档位 |
| `0x04` | 硬件音量 | 查表编码（映射为 61 项硬件步进寄存器） |
| `0x05` | 声道平衡 | 37 档差分编码调节左右平衡 |
| `0x06` | LED 控制 | 开关指示灯 |
| `0x07` | 防爆音 (Depop) | 开关插拔消噪保护机制 |
| `0xA0` | 读固件版本 | 触发后读取固件信息 |
| `0xA2` | 读当前状态 | 回读当前音量档位与左右平衡值 |
