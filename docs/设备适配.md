# 设备适配指南

> 某款设备能不能用？不能用时怎么加进来？

---

## 一、判定规则

本工具的协议选择**只由 VID（厂商号）决定，与 PID（产品号）无关**。

| VID | 阵营 | 通信方式 | 驱动要求 |
| :--- | :--- | :--- | :--- |
| `13058` | TTGK | USB HID 中断端点 | Windows 原生免驱 |
| `12230` | 旋润 | USB 控制传输 | 需 WinUSB（用 Zadig 安装） |

PID 的唯一作用是**在产品表里查出显示名和图标**。协议层代码（`devices/ttgk.py`、`devices/xuanrun.py`）中没有任何 PID 分支 —— 可用以下命令自行验证：

```bash
grep -rn "pid" app/yunji/devices/ttgk.py app/yunji/devices/xuanrun.py
# 无输出即表示协议与 PID 无关
```

### 这意味着什么

- **同阵营的新型号**（例如 TTGK 出了新的「剑」）通常**无需改代码**，把 PID 加进产品表即可。
- **不同 VID 的设备**需要先确认它走哪种协议（HID 还是控制传输），可能要新增适配代码。

## 二、查设备的 VID / PID

```bash
python tools/list_usb_devices.py
```

输出会把「已收录」与「未收录」的设备分开列出，例如：

```
=== 云姬相关设备 ===
状态     品牌     VID     PID     通道       名称
已知     TTGK   13058   17388   HID/USB  凌云剑
未知     TTGK   13058   17399   HID      （未收录）
```

也可以在 Windows「设备管理器 → 通用串行总线设备」中右键属性 → 详细信息 → 硬件 ID 查看
（形如 `USB\VID_13058&PID_43F7`，其中 `43F7` 是十六进制，需转成十进制）。

## 三、添加设备（两种方式）

### 方式 A：本地覆盖（推荐，无需改代码、无需重新打包）

本工具支持资源覆盖机制：`%APPDATA%\YunjiSettings\assets-override\` 下的内容优先于内置资源。

1. 创建目录 `%APPDATA%\YunjiSettings\assets-override\product-list\`
2. 把 `app/assets/product-list/product-list.json` 复制进去
3. 在对应厂商的 `products` 数组里追加一项：

```json
{
  "id": 17399,
  "name": "青云剑",
  "icon": "ic_dev_default",
  "isValid": true,
  "additionalInfo": ["cb5100"]
}
```

字段说明：

| 字段 | 含义 |
| :--- | :--- |
| `id` | **设备的 PID（十进制）** |
| `name` | 界面显示名 |
| `icon` | 图标文件名（不含扩展名）；`ic_dev_default` 是中性占位图标 |
| `isValid` | 是否可用。设为 `false` 时列表里会显示为不可用 |
| `additionalInfo` | 芯片类型，取 `"cb1200"` 或 `"cb5100"` —— **这一项决定 EQ 参数上限，填错会导致写入越界** |

4. 重启软件

> 图标：把自定义 PNG 放到 `assets-override/icons/` 下，文件名与 `icon` 字段一致即可。
> 尺寸建议 128×128。

### 方式 B：提交到内置产品表

如果你希望所有用户都能直接支持，欢迎提 PR 修改 `app/assets/product-list/product-list.json`。
请在 PR 描述中说明设备型号与实测结果。

## 四、芯片类型（cb1200 / cb5100）怎么定

`additionalInfo` 决定的是 **EQ 增益范围与滤波器数量**，不是通信协议：

| 芯片 | 说明 |
| :--- | :--- |
| `cb1200` | 对应 Q25、云中剑等 |
| `cb5100` | 对应凌云剑等 |

**判断方法**：先按 `cb5100` 试，进入 ProEQ 页观察频段数与增益范围是否与设备实际能力一致。
若写入后参数异常（例如增益被截断），改用 `cb1200` 再试。

⚠️ 若该型号的芯片两者都不是，需要先逆向其 EQ 参数格式，见下一节。

## 五、需要逆向的情况

出现以下任一情况时，仅靠加产品表不够，需要分析设备协议：

1. VID 不是 `13058` / `12230`
2. 设备能打开但读不出数据（响应格式不同）
3. EQ 写入后不生效或设备异常

参考做法：

1. 拿到官方 App 的安装包（APK）
2. 用 jadx 反编译，在 `com/yunji/setting/` 下找对应的设备 Activity / Helper
3. 对照 [协议参考.md](协议参考.md) 中的报文结构，找出差异
4. 在 `app/yunji/devices/` 下新增协议实现，并在 `scanner.brand_of()` 里登记新的 VID

## 六、已知不支持的形态

- **左右声道独立 EQ**：硬件协议是单套 8 段参数，`CMD_BALANCE` 只是整体 L/R 衰减配对，
  不是分声道滤波。这是硬件限制，无法通过软件实现。

## 七、故障排查：列表已连接但读取失败

这是最常见的报告类型。**「能被枚举」与「能通信」是两件事** —— 前者只要求设备正常枚举，
后者要求驱动绑定正确且链路稳定。

### 7.1 先跑诊断脚本

```bash
python tools/probe_xuanrun.py            # 旋润设备（VID 12230）
python tools/probe_xuanrun.py --pid 61692
python tools/probe_xuanrun.py --loop 10  # 连续读 10 次，看稳定性
```

脚本按四层顺序报告：枚举 → 描述符 → `set_configuration` → 厂商控制传输。

### 7.2 错误分类与处理

软件会把 libusb 错误归为四类，并在界面上直接显示：

| 类别 | 典型 errno | 含义 | 处理 |
| :--- | :--- | :--- | :--- |
| `stale` | -4 `NO_DEVICE` | 句柄失效，设备被重新枚举 | 隔离器供电不足 / 链路抖动；软件会自动尝试重新枚举一次 |
| `unsupported` | -12 `NOT_SUPPORTED`、-9 `PIPE` | 驱动未绑定，或接口号不符 | 用 Zadig 重新安装 WinUSB |
| `timeout` | -7 | 设备未在超时内响应 | 隔离器延迟过大或供电不足 |
| `io` | -1 | 传输 I/O 错误 | 线材 / 隔离器质量 |

`stale` 与 `unsupported` 被标记为「重试无意义」——前者需要重新枚举句柄，后者需要用户干预，
因此不会浪费 3 次超时等待。

### 7.3 USB 隔离器的典型问题

隔离器（尤其是 ADuM3160 / ADuM4160 方案）会引入三类问题：

1. **供电受限**（通常仅 100 mA）：设备能枚举，但首次操作时掉电重连 → 表现为 `stale`。
   **对策：换用带外部供电的隔离器。**
2. **只支持全速 12 Mbps**：本身不影响控制传输，但部分设备在全速下时序不同。
3. **不透传厂商自定义控制请求**：部分低端隔离器只透传标准请求，厂商请求会被丢弃 →
   表现为 `timeout`。**这类隔离器无法通过软件绕过。**

此外，**经隔离器后设备可能是新的 USB 设备实例**。如果之前用 Zadig 直接给设备绑过 WinUSB，
经隔离器后可能需要在新的实例上重新绑定一次。

### 7.4 软件侧的应对

| 措施 | 说明 |
| :--- | :--- |
| 控制传输重试 | 最多 3 次，退避延时 50/100 ms；写入到读取的间隔随重试次数放宽（隔离器增加延迟） |
| 句柄自动恢复 | 遇到 `stale` 时自动按 VID/PID 重新枚举并重试一次，不消耗重试次数 |
| 真实错误透出 | 页面直接显示失败原因与处理建议，同时写入 `%APPDATA%\YunjiSettings\logs\yunji.log` |
| 手动重试按钮 | 读取失败后出现「重试连接」，可原地恢复，无需退出页面 |
