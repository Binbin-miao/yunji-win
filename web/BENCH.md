# 曲线区性能基准

16 号工单的验收数据。基准不是「跑一次好看」，而是**可复现**：任何人用下面两条命令都能拿到同口径的数。

## 怎么跑

```bash
cd web
npx vite --port 4174
# 浏览器打开 http://127.0.0.1:4174/yunji-win/web/bench/
```

无头抓数（适合贴进 PR / 作回归对比）：

```bash
chrome --headless=new --disable-gpu --dump-dom \
  http://127.0.0.1:4174/yunji-win/web/bench/ | grep -A20 '<pre'
```

页面里的 `document.title` 也会写成 `BENCH frame=…ms old=…ms`，方便脚本直接抓。

## 测的是什么

| 项 | 含义 |
| --- | --- |
| 网格层重画 | 竖线横线刻度画一遍的耗时，只在画布尺寸或纵轴范围变化时发生 |
| 本版每帧 | 清屏 + 曲线/填充/锚点/读数，拖动时每帧都要做 |
| 旧版每帧 | 清屏 + 网格 + 曲线，即优化前「一张画布全量重画」的做法 |
| 发光画法 | 同一条 240 点曲线，`shadowBlur` 与「淡光 + 亮线」两次描边的对比 |
| 拟合 | 100 个频点压成 8 段的耗时 |

三个画布尺寸覆盖：笔记本普通屏、高分屏（dpr 2）、全屏宽（dpr 2）。
每次都是「预热 1 次 + 连跑 200 帧取平均（网格 30 次）」，并在每次绘制后读一个像素强制同步出图——Canvas2D 默认只记录命令，不强制出图就量不到真实栅格化成本。

## 本机实测（2026-10-31）

环境：Windows 11 · Chrome 156 无头模式 · `--disable-gpu`（软件光栅，SwiftShader）· 无头环境**不是**真实 GPU 合成路径，绝对值偏慢，看相对关系。

```
画布                    网格层重画    本版每帧    旧版每帧   省下
960×320 @1x（笔记本常见）        0.040 ms     0.806 ms    0.839 ms     4 %
1280×320 @2x（高分屏）          0.097 ms     1.308 ms    1.393 ms     6 %
1920×480 @2x（全屏宽）          0.163 ms     1.748 ms    1.808 ms     3 %

发光画法（同一条 240 点曲线，只换发光手段）
960×320 @1x                  shadowBlur 0.339 ms → 两次描边 0.158 ms（54 % 更快）
1280×320 @2x                 shadowBlur 1.295 ms → 两次描边 0.335 ms（74 % 更快）
1920×480 @2x                 shadowBlur 3.037 ms → 两次描边 0.477 ms（84 % 更快）

曲线计算    0.196 ms / 240 点（已含在数据层里）
拟合        100 个频点 → 8 段：8.5 ms（160 拟合点 × 5 次迭代）
```

同机重复跑波动约 ±10%，别把 3 % 与 6 % 的差别当真。

## 结论

1. **真正的大头是发光，不是网格。** 原来 `shadowBlur = 10` 在全屏宽高分屏上吃掉 3.04 ms，相当于每帧预算的 18%。换成「7 px 淡光描边 + 2 px 亮线」两次描边后降到 0.48 ms，画面上仍是「亮线 + 柔光」，看不出区别。这一项省下的是**整帧成本的六成**。
2. **网格层分层只值 3–6 %。** 网格本身只有 0.04–0.16 ms，它便宜是因为只有十几条 1 px 直线。把它挪到底层画布仍然值得做：一是每帧少十几条路径命令，二是代码上「网格」和「数据」彻底分开，改一边不会误伤另一边。但**不要把它当成性能救命稻草**。
3. **拟合 8.5 ms 超过不了 16 ms 帧预算，但也接近一半。** 它不再放在点击回调里同步跑：点「拟合成 8 段」后先画出「拟合中…」，下一帧才真正计算，界面不会出现点击无反应的错觉。
4. 顺带修掉一个隐形浪费：旧代码每次重绘都重设 `canvas.width/height`，这会让浏览器**重新分配整块后备存储并清空**，等于每帧都在重建画布。现在只有尺寸真的变了才设。
5. 最慢一档单帧 1.75 ms，60 fps 的 16.7 ms 预算还剩**约 10 倍余量**，连续拖动三秒不会有长任务。

## 形状没变

`web/src/domain/curve.golden.test.ts` 锁住了 06 号工单里那根曲线的 13 个采样点（频率与增益），另外用 2000 点加密采样的插值结果比对，任一处偏差超过 0.05 dB 就失败。性能优化只许改画法，改到形状就红。

## 回归对比

改了绘制逻辑后重跑，把这些数和上表比：

- 单帧耗时**翻倍**以上 → 找是不是又引入了滤镜、模糊或整块渐变重建
- 网格层超过 0.5 ms → 是不是刻度文字在每帧重排
- 拟合超过 30 ms → 看 `eqFit.ts` 的迭代次数与拟合点数有没有被改动

数值只在本机同环境内可比；换了机器请重新记录一份并注明环境。
